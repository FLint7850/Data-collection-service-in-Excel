# Нормализация списков программ

Один алгоритм применяется к данным парсера, исходного CSV, ChatGPT и ручному подтверждению итогового значения. Он работает для списков программ стирки, мойки, сушки, дополнительных программ и списков в группе «Программы», в том числе для ранее импортированных шаблонов без признака составного значения. Количество программ, время, индикация и логические характеристики обрабатываются по обычным правилам своих полей.

## Допустимый набор

Набор определяется активным справочником конкретного поля выбранного шаблона. Готовые значения разбиваются на отдельные составные названия: `Хлопок/Шерсть/Полоскание и отжим` задаёт три допустимые программы. Неактивные значения не участвуют. Справочник и его идентификаторы при разборе не изменяются.

Синонимы берутся из сохранённых данных активных значений этого поля. Названия программ и смысловые соответствия не зашиваются в код. Если в справочнике сохранено соответствие «Детское белье» → «Детские вещи», оно применяется; без такого соответствия названия не считаются равными автоматически. Неоднозначный синоним не принимается автоматически; приблизительное сходство не добавляет программу в результат.

Набор названий и синонимов собирается заново при каждом сопоставлении. Добавление, переименование, отключение или удаление значения в справочнике сразу учитывается в следующей обработке. Изменённые и удалённые синонимы также не сохраняются в локальном списке или кэше. Текущая синхронизация OpenCart добавляет новые значения и сохраняет прежние активные записи; они остаются допустимыми, пока не отключены или не удалены в справочнике.

## Алгоритм

1. Собрать допустимые составные названия из полного активного справочника поля, включая готовые комбинации.
2. Для сравнения привести регистр, пробелы, обозначения градусов и минут к единой форме. Исходный текст сохранить для проверки.
3. Распознать список с `/`, настроенным разделителем, запятыми, точками с запятой либо пробелами. Сначала сопоставлять наиболее длинные названия: «Полоскание и отжим» остаётся одной программой. Разделитель внутри скобок остаётся частью названия.
4. Сопоставить каждую найденную программу с допустимым названием или установленным синонимом. Более подробная программа из справочника имеет приоритет. Например, если допустим только «Экспресс 15'», «Экспресс 30'» ему не соответствует. Если справочник содержит базовый «Экспресс», время в источнике может быть уточнением этой программы.
5. Исключить неизвестные названия из итогового атрибута и перечислить их в пояснении. Если допустимых программ не найдено, оставить итог пустым и сохранить исходный факт для проверки. Не переносить программы из другого поля или из ранее заполненного значения.
6. Удалить повторы после сопоставления синонимов, начать каждое составное название с большой буквы, отсортировать названия по алфавиту и соединить через `/`.

Пример для набора `Детские вещи`, `Хлопок`, `Шерсть`, `Полоскание и отжим` с сохранённым синонимом «Детское белье» → «Детские вещи»:

`шерсть; Детское белье; хлопок; Полоскание и отжим; хлопок; Неизвестная программа`

Результат: `Детские вещи/Полоскание и отжим/Хлопок/Шерсть`. Неизвестная программа остаётся в исходных данных и пояснении.

## Предложения без изменения значения

Подтверждение существующего значения источником сохраняется как свидетельство. Если «Было», «Предложение» и «Итог» совпадают, предложение очищается, строка не требует повторного подтверждения и не учитывается в числе предложений. Интерфейс скрывает повторяющееся предложение и его кнопки. Это также учитывается при чтении старых записей.

Статус «Предложение» используется для атрибута, у которого нет исходного значения: источник нашёл значение для заполнения поля шаблона. Если исходное значение уже было, расхождение с источником или необходимость выбрать вариант из справочника относятся к конфликтам, включая исходные значения вне справочника. Альтернативы остаются доступными для ручного выбора, но такой атрибут не попадает в фильтр предложений. Подтверждённое совпадение сохраняет исходное значение без нового предложения.

Для старых обработок при запуске backend однократно исправляются статусы, сводки и счётчики. Ручные подтверждения и технические пропуски сохраняются. Интерфейс также применяет новое правило к старым ответам API.

Новые правила разбора программ применяются при повторной обработке уже разобранных товаров.
