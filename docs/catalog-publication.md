# Создание новых товаров в `/attribute-assistant` (CSV Price Pro)

## Назначение

Существующая обработка характеристик не меняется: «Обогатить существующий товар» работает как раньше. Новый режим «Создать новые товары (черновики)» предназначен для **новых** карточек из внешних URL. Товар в магазин при обработке URL **не создаётся**, изображения **не скачиваются** и **не копируются** на сервер магазина.

**Статус реализации:** полнофункциональная стадия подготовки и проверяемого CSV-экспорта. Автоматическая запись товаров/загрузка изображений через собственный API ocStore в этот выпуск **не входит**: имеющийся Attribut&co API поддерживает синхронизацию/чтение шаблонов, но не подтверждённую безопасную операцию `createProduct`. Изобретать её без исходников модификатора и стенда магазина нельзя. Для фактического добавления в магазин используется CSV Price Pro.

## Как добавить товар

1. Откройте `/attribute-assistant` → «Ссылки сайта» → **Создать новые товары (черновики)**.
2. Вставьте HTTP(S)-ссылки на товары других сайтов (по одной на строке), **выберите точный шаблон категории**. Без выбора шаблона создание запрещено. По URL загружаются HTML и JSON-LD, а не сами изображения.
3. В обработке откройте товар. В панели «Черновик нового товара» перепроверьте модель, название, **категорию назначения**, цену и список фотографий. Первая фотография — главная. Значения во внешнем источнике не гарантируют достоверность; не подменяйте ими проверку человеком.
4. Обработайте значения атрибутов обычными средствами Attribute Assistant. В результате должны присутствовать **все и только** поля шаблона; пустые поля допустимы, неподтверждённые значения экспортировать нельзя.
5. Нажмите **Сохранить черновик** → **Проверить шаблон**. Если шаблон был изменён после получения карточки, экспорт блокируется до повторного согласования.
6. Для CSV Price Pro выбирайте один из вариантов:
   - **CSV с `_ATTRIBUTES_`**: 9 колонок. Можно импортировать одним проходом, только если профиль CSV Price Pro поддерживает столбец и его формат `Группа|Атрибут|Значение` (включая пустые значения).
   - **CSV без `_ATTRIBUTES_`**: 8 колонок. После добавления товара импортируйте отдельный CSV характеристик из кнопки **«Отдельный CSV атрибутов»**. Второй профиль должен **обновлять атрибуты по модели**, а не создавать дубли.
7. В интерфейсе CSV Price Pro выберите соответствующий профиль для **создания нового товара**, проверьте сопоставление категорий, производителей, полей и наличие доступа для скачивания изображений. **Только при подтверждённом импорте** CSV Price Pro может скачать изображения на сервер магазина. На этапе обработки/экспорта загрузки изображений нет.
8. Проверьте созданную карточку в админке ocStore перед её публикацией: категория, производитель, цена, основное/дополнительные изображения, **все атрибуты и пустые атрибуты**. При необходимости выполните отдельно синхронизацию атрибутов на стороне магазина.

**Внимание:** реализация обязательного наличия *пустых* атрибутов на уровне БД ocStore зависит от конкретного профиля CSV Price Pro. Если модуль пропускает пустые значения, никакой экспорт CSV не гарантирует присутствие этих связей на сайте. Для абсолютной гарантии потребуется доработка модификатора магазина с записью/сверкой `product_attribute` по remote `attribute_id` и `language_id`. В этот выпуск такой операции нет.

## Правила экспорта

- Кодировка `CP1251`, разделитель `;`, окончания строк `CRLF`, стандартное CSV-экранирование.
- Основные поля: `_CATEGORY_`, `_NAME_`, `_MODEL_`, `_MANUFACTURER_`, `_PRICE_`, `_IMAGE_`, `_IMAGES_`, `_PRODUCT_IMAGES_`.
- `_IMAGE_` — URL главного изображения; `_IMAGES_` — дополнительные URL через **запятую**, `_PRODUCT_IMAGES_` — **все** URL через запятую. Именно так устроен приложенный образец. Изображения остаются удалёнными ссылками до фактического импорта.
- Опционально добавляется `_ATTRIBUTES_`: одна строка на каждое поле шаблона в заданном порядке, включая пустые (`Группа|Название|`). Атрибуты, не входящие в шаблон, игнорируются при экспорте, но могут оставаться видимыми для разбора.
- При экспорте всех новых товаров выбирается текущая обработка; **если хотя бы один товар не прошёл проверку, массовый экспорт отклоняется целиком**. Можно исправить данные или подготовить отдельный товар.
- Отдельный CSV характеристик содержит `_MODEL_` и `_ATTRIBUTES_`.
- Каждая операция генерации CSV регистрирует временный файл в транзакционной файловой системе проекта: файл публикуется только при успешном коммите SQL-транзакции.
- Выбранная категория для нового товара изначально берётся **из локального шаблона**, а не из структуры каталога внешнего магазина.
- Поддерживаются URL изображений HTTPS; URL с локальными доменами, IP-литералами, пользовательскими учётными данными отклоняются. Фактическую сетевую безопасность скачивания обеспечивают средства магазина/импортера, которые следует настроить отдельно.

## API (все методы требуют авторизации интерфейса)

| Метод | Назначение |
|---|---|
| `POST /api/attribute-assistant/batches/urls` | `purpose:"catalog"`, `template_id`, `urls`, опциональный `shop_id` |
| `GET /api/attribute-assistant/catalog/shops` | Активные подключённые магазины |
| `GET /api/attribute-assistant/catalog/products/:id/preflight` | Структурная проверка и предупреждения |
| `PATCH /api/attribute-assistant/catalog/products/:id` | Изменение реквизитов и HTTPS URL картинок с `expected_version` |
| `POST /api/attribute-assistant/catalog/batches/:id/export` | Создать CSV по `product_ids` или `all:true`; `include_attributes` |
| `POST /api/attribute-assistant/catalog/batches/:id/attributes` | Второй CSV только атрибутов по `product_ids` |
| `GET /api/attribute-assistant/catalog/exports/:filename` | Скачать файл после успешного коммита |

Интерфейс не делает запросов записи в OpenCart; `shop_id` в этом выпуске используется для обозначения целевого магазина и проверки локальных коллизий моделей, не как автоматическое разрешение на публикацию.

## Миграция/совместимость

Добавлена таблица `attribute_catalog_drafts` через `models.py` и миграция `alembic/versions/20261026_0009_catalog_drafts.py`. Стандартный запуск приложения использует `init_db()` и `Base.metadata.create_all()` для отсутствующих таблиц. Таблицы характеристик и существующие записи остаются на месте. **Перед обновлением остановите приложение и сделайте резервную копию**; не копируйте только `.db`, пока он используется с SQLite WAL.

## Обновление Docker-сервера (после проверок на стенде)

Из каталога **старой** инсталляции остановите контейнеры (`docker compose down`). Сделайте архив `data/`, `storage/`, `feeds/`, `exports/`, `.env` и пользовательских конфигураций. Разверните **исходники** выпуска поверх старых, **не перезаписывая** данные, `.env` и собственные конфигурации. Выполните:

```bash
docker compose config
docker compose up -d --build
docker compose ps
docker compose logs --tail 150 parser frontend
```

После запуска зайдите в обработку и проверьте создание тестового черновика, скачивание обеих разновидностей CSV и сохранность существующих обработок. Не проводите импорт CSV в боевой магазин до успешного окончания тестов в копии магазина. На случай отката сохраните старый архив исходников и полную холодную копию SQLite/WAL и хранилища.
